# データ・連携仕様

更新日: 2026-11-01（日本時間）。体験版の初版保存形式は **v1**。合格条件は[完成基準](completion-criteria.md)、検証データ・結果は[手動チェックリスト](manual-acceptance-checklist.md)、本文・素材の変更は[編集ガイド](editing-guide.md)を参照する。

## 保存単位と更新順序

- AsyncStorageの`@my-june/app-state-v1`へAppState全体を1件のJSONで保存する。`schemaVersion: 1`を使用する。DB・クラウド同期・別ログファイルはない。
- [AppStateProvider](../src/state/AppStateProvider.tsx)の変更操作はPromiseキューで直列化し、最新の`stateRef`から次状態を作る。原則は **検証→次状態→Repository保存→共有状態反映**。保存失敗では業務状態を確定せず、後続キューは継続する。Provider外の別プロセスとの排他制御はない。
- 例外は計測停止。ライフサイクル／フォーカス変更時にキューを待たず区間を閉じ、メモリへ同期反映する。保存中に止まった同じセッションを古い実行状態へ戻さない。停止／再開保存に失敗すると再試行成功まで停止し、再開は保存後に最新の資格を確認して現在時刻から行う。
- 読込時は実行中タイマーを停止へ正規化して保存する。未確定区間・終了中の不明な時間は加算しない。保存済み累積は保持し、最後の停止以降の未保存区間は損失を許容する。
- BGM／SEは保存済み値と一時プレビューを分ける。操作中だけ対象のプレビューを使い、他項目の保存へ混ぜない。指を離すか非ドラッグ操作で保存し、失敗時はプレビューを解除して保存済み音量へ戻す。希望値で再試行できる。
- ユーザー名・通知時刻も保存後に反映し、その後でOSの予約へ同期する。OS予約失敗では保存済み設定を戻さない。

実装: [Repository](../src/storage/appStateRepository.ts)、[状態型](../src/domain/common/types.ts)。

## AppState

| 項目 | 型・初期値・制約 |
| --- | --- |
| `schemaVersion` | 1 |
| `bgmVolume` / `seVolume` | それぞれ0〜1の有限数。初期0.3 / 1。独立して保存 |
| `userName` | string、初期「ゲスト」。保存データは空白だけを拒否。長い旧値を読込時に切らない |
| `notificationHour` / `notificationMinute` | 時0〜23・分0〜59の整数、初期21:30 |
| `defaultTimerMinutes` | 0〜1435の整数・5分刻み、初期25。進行中タイマーには影響しない |
| `taskName` | string、初期空。登録・改名時trim、進捗は維持 |
| `totalNt` / `totalCompletions` | 非負の安全な整数、初期0。完了で加算、NTは購入で減算 |
| `lastCompletionDate` | 最後の終了日のYYYY-MM-DDまたはnull |
| `unlockedStories` | `{ episodeId, unlockedDate }[]`、初期空。実在する話ID・日付、話ID重複なし |
| `storyRouteProgress` | 話ID→`{ firstSelectedRouteId?, extraUnlockedRouteIds }`、初期空。初回無料選択と追加購入を分離 |
| `purchasedSideStoryIds` / `announcedSideStoryIds` | 購入済み／入荷告知済みの商品ID。重複なしの正の安全な整数配列、初期空 |
| `diaryLogs` | 完了ログ配列、初期空 |
| `activeTimer` | 下記タイマーまたはnull。同時に最大1セッション |

編集UIはタスク80・名前40・日記1000のUTF-16コード単位で入力制限・文字数表示する。上限を超える旧値は保持し、短く編集でき、超過中はOKと保存を止める。名前保存APIだけは従来のtrim後1〜40 Unicodeコードポイント検証を維持する。保存層は名前・タスク・日記の長さを理由に旧データを拒否／切捨てしない。

### タイマーと日記ログ

| データ | 項目・意味 |
| --- | --- |
| `SessionStart` | `startedAt`（ms）、`startedDate`（ローカルYYYY-MM-DD）、`startedTime`（HH:MM:SS）。開始ボタン呼出時、保存キューを待つ前に取得。後から日付を再計算しない |
| `ActiveTimer` | `sessionId`、`plannedSeconds`（0〜86100の整数）、`startedTaskName`、`startInfo`（SessionStart）、`accumulatedMs`（閉じた区間の累積）、`runningSince`（実行区間の開始msまたはnull） |
| `DiaryLog` | `id=sessionId`（重複不可）、`startInfo`、`logDate`、`completedAt`、`completedDate`、`completedTime`（HH:MM）、`totalTimerSeconds`、`diary`、`unlockedEpisodeId`（解放なしはnull） |

- 経過msは`accumulatedMs + max(0, now - runningSince)`（実行中のみ）。NTと記録秒数は`floor(経過ms / 1000)`。予定達成はmsで判定する。Date.nowを使い、単調増加時計・サーバー時刻は使わない。
- 停止・再開で`startInfo`を変えない。新規ログの`logDate`は開始日、完了・日次解放は終了ボタンの日。日記保存が翌日でも終了情報を変えず、日跨ぎの時間を分割しない。
- カレンダーの印・一覧・合計・前後の記録日への移動は`logDate`を使う。キャンセルはログを作らない。すべてのタイマー・ログに開始情報を必須とする。
- ログにはタスク名・予定時間・獲得NT・日記更新時刻・タイムゾーンID・キャンセル履歴を保存しない。終了時刻を開始時刻の代用にしない。
- 今日の完了は`lastCompletionDate === today`。ホームはローカル0時・前景復帰・30秒ごとの時計再確認で表示を更新し、保存状態を日次リセットしない。時計／タイムゾーンの変更や日付往復に対する厳密な日次制約は保証しない。

実装: [timer](../src/domain/timer.ts)、[completion](../src/domain/completion.ts)、[useLocalToday](../src/hooks/useLocalToday.ts)。

## 操作ごとの保存対象

| 操作 | 更新内容 |
| --- | --- |
| タスク／名前／通知時刻／デフォルト時間／各音量 | 対象項目だけ変更し、キュー内の他の最新値を保持 |
| 開始 | `activeTimer`作成。既存セッションがあればそのまま返す |
| 予定到達前のキャンセル | `activeTimer=null`のみ。ログ・報酬なし |
| 正常完了 | NT・累計・最終終了日更新、ログ追加、当日初回なら次話解放、タイマー消去 |
| 日記編集 | 対象ログの`diary`だけtrimして保存。空可・1000 UTF-16単位以下。時間・NT・回数・解放を変えない |
| 初回分岐／追加分岐購入 | 無料初回IDの記録／設定価格のNT減算と追加分岐ID追加 |
| サイド購入／入荷告知 | 設定価格のNT減算と購入ID追加／未告知ID追加 |

日記保存失敗では元の記録と下書きを保持し、取消は下書きだけを破棄する。通常データの全消去、タスク／日記削除、購入取消／返金、製品版エクスポート／インポートは実装していない。

## 保存形式の検証と互換性

[parsePersistedState / validateAppState](../src/storage/appStateRepository.ts)が初版v1の型・範囲・必須項目・日付・重複を検証する。タイマー・ログの`startInfo`は全3項目が必須で、nullを許容せず、ログ所属日と開始日は一致させる。ログの`completedTime`も必須。不正JSON・未対応版・検証不合格は補正保存せず保全する。有効なデータの読込だけではRepositoryから書き戻さない。

- 体験版を最初の保存形式とし、配布前に使った開発用の番号なし／v0〜v14からの移行処理は持たない。既存のテスト端末は引き継がず、読込エラー画面の「退避と初期化の内容を確認」→「退避して初期化する」で初版v1へリセットする。以前の開発用v1も必須項目不足のため読込対象外。
- 将来の形式変更時は、その形式のデータを持つ利用者がすでにいるか確認してから互換処理の要否を決める。未配布の形式ごとに移行を追加しない。配布後の記録・残高・権利は維持する。
- 本文・価格・条件変更では権利IDを維持する。IDの削除／変更も、既存利用者の保存済み権利への影響を確認して必要な移行を設計する。
- 検証の限界: 分岐IDは文字列・重複を確認するが実在分岐と照合しない。購入／告知IDも商品カタログと照合しない。話解放と分岐進捗、最終終了日とログの完全な意味的整合は保証しない。通常購入APIは実在性を再確認する。

## 破損データの保全

- 読込不合格では`PreservedDataError`にし、通常画面と通常保存を止め、主キー原文を保持する。保存前にも現在の主キーを再検証し、不正なら上書きしない。
- 再読込または確認付き初期化へ進める。明示的初期化時だけ`@my-june/recovery/<時刻>-<乱数>`へ原文を退避し、退避内容を照合、主キーが変わっていないことを再確認してから初期値へ置換する。
- 退避先衝突・退避／照合失敗・主キー変更では初期化を中止する。退避は自動削除せず、アプリ内の自動修復・退避からの自動復元はない。
- iPhoneでの初版v1の再起動後保持・エラー表示・退避と初期化・保存失敗等は未検証。過去の補助確認を現行形式や実機の合格へ流用しない。

## 通知と外部連携

- [通知同期](../src/notifications/reminderNotifications.ts)はexpo-notificationsを使用。iPhone端末内で保存済みの名前・ローカル時刻を毎日繰り返す。固定ID`myjune-daily-timer-reminder`で置換し、更新前に取り消さないため失敗時は旧予約が残り得る。許可なしなら予約を取り消す。iOS以外は未対応と表示する。
- 設定変更・起動・前景復帰・再試行で同期する。OSの許可／予約状態は保存データと別管理。現行の本文は`{userName}～　来て～`で、[完成基準A11](completion-criteria.md#a11-毎日のローカル通知)とは差がある。
- ログイン・サーバー認可・業務API・クラウド同期・分析／広告／クラッシュ送信はアプリに実装していない。NTは実決済を伴わない端末内ポイント。URL引数でも保存済み権利を確認する。
- 本文・素材・設定はアプリに同梱し、変更には再配布が必要。編集先は[編集ガイド](editing-guide.md)。
- マイク・位置情報は要求しない。expo-audioの録音権限・録音・背景再生は設定で無効化しているが、生成済みManifest／Info.plist・製品バイナリは未検証。通知を含むネイティブ変更後は開発ビルドを再作成する。
- JSONの暗号化・署名・改ざん検知・サーバー残高照合はない。OSの保護・バックアップ挙動は未検証。日記の保存期間・端末変更時の移行・バックアップ・長期保存サイズ／全体更新性能は未整備。
