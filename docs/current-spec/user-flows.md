## 1. 初回起動・タスク登録

**開始条件**: 保存キーが存在しない。

1. Repositoryが空の初期状態を返す。NT0、累計0、タスク名空、解放・購入・ログなし。
2. レイアウトが読込表示からホームへ移る。
3. タスク名モーダルが必須として開く。空白だけの入力はエラー。
4. 名前を保存する。前後の空白を除去し、スナップショット保存成功後に共有状態へ反映する。
5. モーダルが閉じ、集中モード開始が有効になる。

**結果**: タスク1件が端末内に保存される。ユーザー名入力・アカウント作成はない。

**失敗・例外**: ストレージ読込例外は再読込画面。タスク保存例外は入力モーダルにエラーを表示する。不正JSON等は元データを保護し、再読込または確認付き退避・初期化へ進める。自動初期化しない（[データ仕様](data-integrations.md)参照）。

根拠: [load/createInitialAppState](../../src/storage/appStateRepository.ts)、[ホーム](../../app/index.tsx)、[タスク名モーダル](../../src/components/home/TaskNameModal.tsx)、[setTaskName](../../src/state/AppStateProvider.tsx)。

## 2. 集中開始・予定到達・延長

**開始条件**: ホームにタスク名があり、進行中タイマーがない。

1. 集中モードを開始→時間設定。初期値25分。
2. ±5分/±1時間で0分〜23時間55分を設定する。
3. 開始を押した呼出時、保存キューの待機前に時刻ms・端末ローカル日付・HH:MM:SSを取得する。セッションID・設定秒数・開始時タスク名・累積0ms・停止状態と一緒に保存する。
4. 保存成功後に`/timer`へpush。アプリactiveかつ画面focusedになると実行区間を開始して保存する。
5. 表示は1秒周期で更新する。経過時間は区間の開始時刻との差を含むミリ秒で計算する。
6. 予定時間到達で「終了して記録」が有効になり、残り時間から延長時間へ切り替わる。自動で完了・保存はしない。

**結果**: 実際に計測した区間のみを集中時間として累積。NT表示は獲得予定で、この段階では残高を増やさない。

**失敗・例外**: 開始保存失敗は設定モーダルにエラー。既存タイマーがある場合は新規作成せず再開する。0分では即座に終了可能で、経過秒数0でも完了・話解放が可能。内部APIの検証は秒単位の整数・範囲のみで、5分単位や名前の存在は強制しない。

根拠: [設定フック](../../src/hooks/useTimerSetup.ts)、[startTimer/assertPlannedSeconds](../../src/state/AppStateProvider.tsx)、[時間計算](../../src/domain/timer.ts)、[画面](../../app/timer.tsx)。

## 3. 中断・画面復帰・再起動

**開始条件**: 進行中セッションがある。

| 操作・変化 | コード上の処理 | 結果 |
| --- | --- | --- |
| アプリがinactive/backgroundになる | AppState changeの時刻で区間を閉じ、累積msと`runningSince=null`を保存 | 停止 |
| タイマー画面からフォーカスが外れる | useFocusEffectのcleanupから停止を要求 | 停止 |
| activeかつタイマー画面focusedに戻る | 新しい`runningSince`を設定して保存 | 再計測 |
| ホームから再開バナーを押す | 同じセッションを`/timer`で開く | 設定時間・開始時タスク名・元の開始情報を維持 |
| アプリを再起動する | 保存済み実行区間は`runningSince=null`へ正規化。不明な区間は加算しない | 既存累積から再開可能 |
| 省電力黒画面を表示 | ルートを変えず標準Modalを重ねる | 計測継続を意図した実装 |

**失敗・例外**: 停止は保存前に同期反映し、失敗通知を表示する。再試行の保存成功まで停止し、現在のactive/focused条件を再確認して再開する。保存中の停止を古い書込結果で巻き戻さない。強制終了直前の未保存区間は失ってもよいが、保存済み累積は保持し、不明時間を補填しない。元の開始情報も再起動後に保持する。旧タイマーは開始情報なしのまま扱う。ロック・黒画面等の実際のイベントはiPhone実機未検証。

根拠: [applyTimerEligibility/normalizeHydratedState](../../src/state/AppStateProvider.tsx)、[useFocusEffect](../../src/hooks/useTimerLogic.ts)、[pauseTimer/resumeTimer](../../src/domain/timer.ts)、[黒画面](../../app/timer.tsx)。

## 4. 期限前キャンセル

**開始条件**: 実集中時間が予定秒数未満。

1. キャンセルを押し、確認Alertを表示。
2. 「続ける」なら計測を継続。
3. 「キャンセルする」なら確定時刻で期限を再判定。
4. 期限前なら`activeTimer=null`を保存してホームへ戻る。

**結果**: NT、累計完了、最終完了日、話解放、日記ログは増えない。キャンセル履歴も残らない。

**失敗・例外**: 確認中に期限到達するとキャンセル不可になる。現在の例外メッセージは「予定時間が終わるまで終了できません。」で、期限後キャンセル拒否の説明としては一致しない。保存失敗はタイマー画面にエラーを出す。

根拠: [handleCancel](../../src/hooks/useTimerLogic.ts)、[cancelTimer](../../src/domain/completion.ts)、[ProviderのcancelTimer/TimerNotReadyError](../../src/state/AppStateProvider.tsx)。

## 5. 終了・日記・報酬・話解放

**開始条件**: 実集中時間が予定秒数以上。

1. 「終了して記録」を押した時刻を取得し、その時刻で計測停止を保存する。
2. 日記モーダルを開く。日記は空でもよい。入力時間は集中時間へ加算しない。
3. 「戻る」ならモーダルを閉じ、active/focusedなら計測を再開する。下書きは同じ画面内では保持する。
4. 「保存して終了」なら、終了ボタンを押した時刻を使って完了条件を再確認する。
5. 実集中msを秒へ切り捨て、同じ数値のNTを残高へ加算。累計完了+1、最終完了日を更新し、開始情報を継承した日記ログを1件追加、タイマーを消す。
6. その日初回かつ未解放のメイン話があれば、順番に次の1話を追加する。
7. 全変更を1件のJSONとして保存。成功後に遷移先を1つ確定し、削除防止解除の描画後、新規解放ありなら`/story`へreplace、なければホームへdismissToする。

**結果**: 延長を含む集中秒数で報酬。同日2回目以降も報酬・累計・日記は増えるが話解放はない。全14話解放後も完了・報酬・日記は続く。

**日付の事実**: 完了・日次解放は終了ボタンの時刻で判定する。23:59に終了して翌日00:01に日記保存しても完了日は前日。ログの所属日は開始ボタンのローカル日付。10/15 23:50開始→10/16 00:20終了では、全実集中時間を10/15のログと合計へ含め、今日の完了・解放は10/16。停止時間を含めず、日付境界で分割しない。開始情報のない旧タイマーだけは互換動作として終了日所属・開始時刻「記録なし」とする。

**失敗・例外**: 停止保存が失敗しても、終了時刻を保持した日記を開き、計測は止めたまま再試行できる。完了保存失敗時はモーダル内エラー、報酬・完了は共有状態へ反映しない。処理をキューで直列化し、セッション消去後の二度目の完了は拒否する。UIの多重操作・保存後の画面遷移競合は実機で未検証。

**ホームの当日表示**: ローカル0時のタイマーとactive復帰で当日を更新し、30秒ごとにも時計を再確認する。本日初回前・本日解放済み・全話解放済みで案内を切り替える。全話後も完了・ログ・NTを保存する。カタログは全14話。全解放後も完了・NT・ログは継続。

根拠: [openDiary/handleFinish](../../src/hooks/useTimerLogic.ts)、[completeTimer/nextUnlockedStory](../../src/domain/completion.ts)、[enqueue/finishTimer](../../src/state/AppStateProvider.tsx)、[DiaryModal](../../src/components/timer/DiaryModal.tsx)。

## 6. 会話読了・分岐・メモリー

**開始条件**: 該当メイン話を解放済み。

1. 新規解放の完了保存後の自動遷移、またはメモリーの再生から開く。
2. 53msごとに1文字を表示。文字送り中のタップで全文、全文後のタップで次の行へ進む。
3. 全14話とも共通前半の後に2択。初めて選ぶ分岐を無料で保存し、選択分岐と共通後半を再生する。各話の選択は独立。
4. 最終行後のタップで保存せず、出発画面に応じて戻る。
5. メモリーでは選択地点で別の分岐を選べる。未解放なら話ごとの設定価格（初期60 NT）の確認パネルを表示。
6. 解放成功後は選択肢へ戻る。解放した選択肢を再度押して再生する。その後は無料。

**結果**: 初回選択と追加購入を話ごとに保持。他の話の本文は変わらない。既読/未読は管理しない。

**失敗・例外**: 途中閉じと再生終了は状態を変更しない。選択済み分岐は保持されるが再生位置は消える。NT不足では解放不可。初回選択・追加解放の保存失敗は画面内エラーで再試行できる。未解放や不正IDの直接URLでは再生不可。

根拠: [本文](../../src/domain/storyData.ts)、[読取フック](../../src/hooks/useStoryReader.ts)、[画面](../../app/story.tsx)、[selectInitialStoryRoute/unlockAdditionalStoryRoute](../../src/state/AppStateProvider.tsx)。

## 7. ショップ入荷・購入・再生・退店

**開始条件**: ホームからショップを開く。初期設定では商品101は常時入荷、102/103は第2話が解放されると入荷。条件は商品ごとの専用設定を参照し、既購入は条件変更後も入荷/再生可能。

1. エトの挨拶を読む。未告知商品があれば入荷セリフも読む。
2. 挨拶読了時に該当商品を告知済みとして保存し、一覧へ。
3. 未購入商品を選び、設定価格（初期60 NT）で解放する確認を確定。
4. 状態キューで入荷・残高・既購入を再判定。設定価格の減算と購入ID追加を同じJSONで保存。
5. 一覧の購入済み商品からサイド会話を再生。読了/閉じるでショップへ戻る。
6. ホームへ戻る操作で退店会話を開始。最後まで読んで閉店してホームへ。退店中の戻る連打ではスキップ/重複遷移しない。

**結果**: 永続購入。再購入は追加課金しない。サイド会話の既読・購入日・再生位置は保存しない。

**失敗・例外**: 入荷前/残高不足はProviderでも拒否。購入失敗はAlert。告知保存失敗は会話上のエラー。サイド会話からのdismissとショップの画面削除防止の相互作用は未検証。

根拠: [ショップ](../../app/shop.tsx)、[サイド会話](../../app/side-story.tsx)、[入荷条件](../../src/domain/sideStory.ts)、[unlockSideStory/announceSideStories](../../src/state/AppStateProvider.tsx)。

## 8. 記録を振り返る・タスク名を変更する

**事実**: カレンダーの日付を押すと、その開始日に所属する正常完了記録と集中時間合計を表示する。各記録は開始時刻HH:MM:SS・集中時間・日記。開始日は個別項目として表示しない。集中時間と合計は時・分・秒。旧ログは元の所属日を維持し、開始時刻「記録なし」。キャンセルは記録も合計も増やさない。前後の日へ移動できる。根拠: [ログ](../../app/log.tsx)、[記録モーダル](../../src/components/log/LogModal.tsx)。

**日記編集**: 記録の「日記を編集する」から保存済みの日記を下書きへコピーする。最大1000文字、空への変更可。「日記を保存」は保存成功後だけ表示へ反映する。保存中は入力・再保存・キャンセルを抑止。失敗時は元の日記と下書きを保持し、エラーを表示して同じ保存ボタンで再試行できる。「編集をキャンセル」は下書きを捨てて戻る。編集中は日付移動・モーダルを閉じる操作を無効にし、OS戻るは編集キャンセルとして扱う。編集では時間・NT・完了回数・解放を変更しない。日記削除機能はなく、空文字の保存で空へ変更する。根拠: [editDiary](../../src/domain/diary.ts)、[updateDiary](../../src/state/AppStateProvider.tsx)、[LogModal](../../src/components/log/LogModal.tsx)。

**事実**: タスク名変更は同じタスクの文字列更新であり、新しいタスクIDや履歴を作らない。既存の完了、話解放、ログをリセットしない。過去ログにタスク名がないため、変更前の名前はログから確認できない。根拠: [setTaskName](../../src/state/AppStateProvider.tsx)、[DiaryLog型](../../src/domain/common/types.ts)。

**確定範囲**: 改名は同じタスクの進捗を引き継ぐ。タスク名のログ表示・記録削除はA05の必須項目に含めない。編集キャンセルとキーボードはユーザー確認済み（環境未記録）。他の編集操作・再起動後表示は実機未検証。
