## 役割と主な連携

- `RootLayout`はSafeAreaProvider → AppFontLoader → AppStateProvider → AppShellの順に配置する。フォント読込成功後に共有状態と画面がマウントされ、フォント失敗時の表示・再試行はAppFontLoaderが担う。
- `AppShell`は保存状態の準備中・読込失敗・通常画面を切り替える。NT、共通ヘッダーとフッター、タイマー保存エラー、BGMエラーと再試行を表示する。
- 初期化の確認UIは`PreservedDataError`の場合に提供する。確認後はProvider経由でRepositoryの退避・照合・初期化を実行し、再読込する。初期化中の操作抑止と失敗表示は画面が持ち、保存キュー・原文保全・保存後の状態確定はProvider／Repositoryが持つ。
- `useScreenBgm`はAppShellの1箇所から呼ぶ。状態準備前・読込エラー時は無効化し、通常時はpathnameと保存済みbgmEnabled、共通音量0.3を渡す。プレイヤー、非同期要求、背景復帰、再試行はフックが持つ。
- `Stack.Screen`の7画面と実ファイル、ホーム・メモリー・ショップからのpush、タイマー完了後のreplace、各画面のdismissToを照合した。会話パラメーターと保存後の遷移、タイマーのフォーカス通知、黒画面が別ルートではなくModalであることも確認した。
- import／export、パスエイリアス、静的require、ルート名・文字列遷移、文書参照を検索した。\_layout.tsxの公開契約はExpo Routerのルートレイアウトとしてのdefault exportであり、直接importがないことを未使用の根拠にはしていない。

## 削除・分割を見送った理由

- `recoveryError`と`isRecovering`は、初期化失敗の通知と実行中の操作抑止に必要。単なる重複状態ではない。
- `StatusMessage`は準備中と読込失敗で使うローカル部品として小さく、汎用化や別ファイル化の必要性は低い。
- タイマー保存とBGMのバナーは短い。2箇所の表示のために新しい共通部品やpropsを増やす利点は小さい。
- Provider、フォント読み込み、BGMの責務はすでに別ファイルへ分離されている。AppShellに残るのは共通UIと接続であり、追加分割による改善は限定的。
- ルート宣言とタイトル、Providerの配置順、BGMフックの常時呼出を維持した。エラー処理やライフサイクル処理を削除していない。

## ExpoAssetエラーと再読み込み後のユーザー確認（同日・追加報告）

続いてユーザーから`Cannot find native module 'ExpoAsset'`と`main has not been registered`の報告を受けた。使用アプリはApp StoreからインストールしたExpo Goとの回答。PC側では`npm.cmd ls expo expo-asset expo-constants expo-modules-core expo-router --depth=1`がexit 0、`npm.cmd run deps:check`が成功、`npm.cmd run doctor`が21/21で成功した。deps:checkの初回は通信制限のEACCESで失敗し、通信を許可した同じコマンドで成功した。起動中MetroのマニフェストはMyJune／SDK 57.0.0であることを確認した。

調査中、ユーザーから「もう一回読み込んだらいけました」と報告があった。再読み込み後の起動はユーザー確認済みとする。機種・iOS・Expo Goの版・表示された画面の詳細は未記録で、他の回帰項目全体の合格には広げない。

途中でSDK不一致により起動不能と断定した説明は撤回する。今回のExpoAssetエラーの原因は未特定であり、キャッシュやSDK差によるものと確定していない。このエラーへの対応として依存・SDK・アプリ構成は変更しておらず、開発ビルドの作成も行っていない。前節までの確認結果は当時の結果として保持する。
