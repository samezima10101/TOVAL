## 価格と入荷条件

[設定ファイル](../src/config/conversationSettings.ts)の該当IDの値だけを変更する。アプリ内管理画面やクラウド管理はない。変更後は開発アプリをReloadし、配布用アプリには更新ビルドが必要。

```ts
// 例: 第4話の「初回無料で選ばなかった側」を75 NTにする。
4: { additionalRoutePriceNt: 75 },

// 例: サイド102を90 NT、第4話解放で入荷にする。
102: { priceNt: 90, requiredUnlockedEpisodeId: 4 },

// 例: サイド103を条件なしにする。
103: { priceNt: 60, requiredUnlockedEpisodeId: null },
```

- 価格は0以上の安全な整数NT。0なら確認後に消費0で解放する。負数・小数・文字列は使わない。
- `requiredUnlockedEpisodeId`は`null`（条件なし）、または実在するメイン話ID（現在1〜14）。その話が`unlockedStories`に含まれた時点で満たす。最後まで読む必要はない。
- 初期値は全追加分岐・全商品60 NT。101条件なし、102/103は第2話解放。
- メイン追加価格は話ごとに1つ。その話で最初に選ぶ分岐はA/Bどちらも無料で、もう一方だけに価格を適用する。選択地点より前に閉じた場合は初回未選択のまま。
- 分岐ボタン・確認パネル・アクセシビリティの読み上げ・残高判定・消費額は同じ価格を参照する。ショップ一覧と購入APIは同じ入荷判定を参照する。
- 購入済みサイドは条件変更後も表示・再生できる。既存の分岐・サイド購入は価格変更後も追加消費なし。告知済みIDも保持し、条件の変更だけでは再告知しない。
- 設定のIDを削除・改名しない。価格や本文の更新を購入のリセットで扱わない。

## 一覧の章分け

[章の設定](../src/config/storyArchive.ts)の`MEMORY_CHAPTERS`と`SHOP_CHAPTERS`を編集する。右上の01〜08は章選択、左側は選んだ章の話一覧、右下は選んだ話の詳細・購入／再生ボタン。ショップは銀色、メモリーは紫系の同じレイアウトを使う。

2026-10-21の最新構成は、章番号を4列で表示し、選択中のタイトルを横長の帯にまとめたシンプルな配置。装飾用の斜め枠・タイムライン・輪郭番号と、重なり順を調整するコードは使わない。

左の話選択はホイール式。スクロールすると上部のタイトル帯に入った話が自動選択され、帯・詳細・操作対象へ反映される。話の表示順は引き続き`storyIds`の順で、章を切り替えると最初の話へ戻る。章名は選択中タイトルの帯に表示する。画面全体は固定し、話一覧と詳細文だけをスクロールする。

初期配置はメイン1〜14とサイド101〜103をそれぞれChapter 1へまとめている。Chapter 2〜8は`storyIds: []`の準備中で選択不可。正式な章分けを受領した状態ではない。例えばメインを2章へ分ける場合は、Chapter 1の`storyIds`を`[1, 2, 3, 4, 5, 6, 7]`、Chapter 2を`[8, 9, 10, 11, 12, 13, 14]`とする。すべての既存IDをいずれか1章へ重複なく配置し、本文・設定・保存データのIDは変えない。

左の「第N話」と詳細の番号は章内の並び順。再生・解放・購入には元の話IDを使う。ショップは既存の入荷判定で表示を絞り、購入済み会話は条件変更後も残る。入荷対象の話を持つ章でも、表示できる話が0件なら「未入荷」として選択不可にする。

詳細の紹介文は共通前半の最初の台詞を使い、未解放のメインはタイトル・本文を隠す。`ROUTE UNLOCK`は取得済み分岐権利の数で、既読数やエンディング発見数ではない。`OPEN`は既存の解放日。サイドは価格または解放済み状態を表示する。

番号は`assets/numbers/`の提供SVGを使用する。ファイル名と字形が一部異なるため、対応は`src/components/common/StoryNumber.tsx`で管理する。元ファイルを維持し、その字形から09〜14と詳細用の輪郭版01〜14を追加した。2026-10-21のシンプル化では章番号のみを表示し、輪郭版の読み込み・表示を廃止した。素材ファイル自体は保持している。現在の章番号は01〜14に対応する。章数を14より増やす場合は番号素材も追加する。

## 本文の編集とID

各話の`title`、`commonBefore`、`routes`内の`label`/`lines`、`commonAfter`を編集する。再生順序は共通前半→選択分岐→共通後半。各行は`id`、`speaker`（`boss`=ジェム/`sub`=アルタ）、`text`、左右の表情を持つ。改行は文字列内の`\n`を使う。行IDは話の中で一意にする。

話ID1〜14、サイドID101〜103、各分岐IDは保存済み権利の識別子なので維持する。第1話は既存の`episode-01-encourage`/`episode-01-bow`、第2〜14話は`episode-NN-route-a`/`episode-NN-route-b`。本文・ラベル・表情だけを変更しても、保存データは変更しない。話/分岐の削除・ID変更は本手順の対象外で、別途移行設計が必要。

既読/未読は管理しない。第2・3話に分岐がなかった既存データは、分岐が未選択なら次回の再生で初回無料選択を行う。選んだことのない分岐を購入済みと推定しない。

保存キー`@my-june/app-state-v1`は維持し、schemaVersionは10。番号なし/v0〜v9を読み込み、旧`isRead`の除去と`bgmEnabled`の補完を含む移行を行う。[データ仕様](data-integrations.md)に版ごとの扱いをまとめる。旧形式で必須だった既読項目の型は移行時に検証し、不正データを黙って受け入れない。解放・分岐購入・サイド購入・告知・NT・完了・ログ・日記・進行中タイマーを維持する。ホームの吹き出し/未読入口は削除し、新規解放時の自動遷移とメモリー再生を使う。メイン/サイドの再生終了時は既読保存を行わず戻る。ショップの入荷告知済み保存は継続する。

## 編集後の確認

`npm run lint`、`npm run typecheck`、`npm run doctor`、`npm run deps:check`を実行する。専用検証データで1話だけ価格を変え、表示・残高境界・実消費を比較する。条件は指定話の未解放/解放済み/条件なしを切り替える。既購入データでも再生し、再課金がないことを確認する。検証のため変更した価格・条件は意図した製品値に戻し、Reloadして確認する。

[手動検証データ・具体的手順・結果](manual-acceptance-checklist.md#conversation-completion)を参照。PCの補助確認をiPhone操作の合格とはしない。

2026-10-22追記: 選択中タイトルは横幅いっぱいの固定帯へ拡大表示（章名も同じ帯へ表示）。追加指示により、スクロール中も帯と文字の位置を固定し、選択された話が変わると文字だけを更新する。一覧の同じ話は非表示にして重複を避ける。リストの表示領域は章番号の横まで上へ延ばし、選択位置は従来のタイトル帯の高さに維持する。画面全体は固定。

### 会話画面の構成と表示調整

メインとサイドは、タイトル・閉じる・再生エラー・固定会話枠・話者名・文字送りを共有する。主な違いは以下のとおり。

| 項目 | メイン（app/story.tsx） | サイド（app/side-story.tsx） |
| --- | --- | --- |
| 再生できる条件 | エピソードとルートの解放状態 | サイド会話の購入状態 |
| 画面の背景 | primary-bg.png | shop-bg.png |
| キャラクター | 表情と発話者を反映 | 表示しない |
| 会話の進行 | 共通前半・分岐・共通後半、追加分岐の解放確認 | 分岐なしの会話 |
| 終了先 | ホームまたはメモリー | ショップ |

コンポーネントの役割は以下に限定する。権利判定・購入・保存・終了先の判断と再生フックの呼び出しは各画面に残し、共通UIへ移さない。背景の選択・描画と共通ヘッダーを避ける画面上部の余白も、各画面で明示する。

| 部品 | 担当 |
| --- | --- |
| [StoryScene](../src/components/story/StoryScene.tsx) | 共通ヘッダー・閉じる・再生エラー、任意のキャラクター領域、固定枠を一度だけ配置 |
| [StoryMessageBox](../src/components/story/StoryMessageBox.tsx)（既定export） | SVG・固定位置・サイズ・内側余白・枠内スクロール。受け取るのは中身と内容の識別子だけ |
| 同ファイルのStoryMessage（名前付きexport） | 話者・本文・文字送り状態・タップ操作。再生結果の必要な項目だけを受け取り、枠を作らない |
| [StoryCharacters](../src/components/story/StoryCharacters.tsx) | キャラクター画像・表情・発話者による濃淡 |
| [StoryChoices](../src/components/story/StoryChoices.tsx)／[StoryUnlockConfirmation](../src/components/story/StoryUnlockConfirmation.tsx) | メイン固有の選択肢・解放確認の中身。枠を作らず、購入処理自体は画面へ委ねる |

StoryDialogueは再作成せず、枠と本文表示をStoryMessageBox.tsxの同じファイルにまとめる。異なる引数の形式を判別して切り替えるAPIは使わない。ショップ挨拶・退店では共通ヘッダーを使わず、同じStoryMessageBoxとStoryMessageを組み合わせる。

会話枠の位置・サイズ・内側余白はStoryMessageBox.tsxのstyles.frameだけで指定する。現在は左右18・下60・高さ210。下位置はロゴフッターの上にある画面領域の下端から測り、数値を増やすと上へ移動する。背景はassets/images/file_textbox.svg。長いセリフや選択肢・解放確認は枠内だけスクロールし、枠は伸縮させない。キャラクターの表示領域はStorySceneで独立して確保する。

内容の識別子（セリフID／選択肢／解放確認）が変わると枠内のスクロール位置だけを先頭へ戻す。枠やキャラクターは再作成せず、文字送りの途中ではスクロール位置をリセットしない。
