### 検証データの再現方法

専用の検証端末・開発ビルドのReact Native DevTools Consoleで使う。実利用データへ投入しない。確認用JSONファイルは置かず、以下の基準データから必要な形式を作る。自動テストではなく、手動投入用のデータである。

```js
const original = await d.readRaw(); // 実行前の原文を手元にも保管
function makeValidationData(version = 7) {
  const data = {
    schemaVersion: version, userName: '', taskName: '記録保全の確認',
    totalNt: 180, totalCompletions: 1, lastCompletionDate: '2026-10-14',
    unlockedStories: [{ episodeId: 1, unlockedDate: '2026-10-14', isRead: true }],
    storyRouteProgress: { 1: { firstSelectedRouteId: 'episode-01-encourage', extraUnlockedRouteIds: [] } },
    purchasedSideStoryIds: [101], announcedSideStoryIds: [101],
    diaryLogs: [{ id: 'saved-session', completedAt: 1791939840000, completedDate: '2026-10-14',
      completedTime: '10:04', totalTimerSeconds: 240, diary: '保持する日記', unlockedEpisodeId: 1 }],
    activeTimer: { sessionId: 'resume-session', plannedSeconds: 0,
      startedTaskName: '記録保全の確認', accumulatedMs: 12000, runningSince: null },
  };
  if (version < 7) delete data.diaryLogs[0].completedTime;
  if (version === 5) delete data.diaryLogs[0].completedDate;
  if (version <= 4) {
    delete data.purchasedSideStoryIds; delete data.announcedSideStoryIds; delete data.diaryLogs;
    if (version === 4) data.isSideStoryUnlocked = true;
  }
  if (version <= 3) delete data.storyRouteProgress;
  if (version < 3) delete data.unlockedStories[0].isRead;
  if (version < 2) {
    data.activeTimer.startedAt = 1791939600000;
    delete data.activeTimer.accumulatedMs; delete data.activeTimer.runningSince;

```

タイマーを離れて保存が終わってから、`await d.replaceRaw(JSON.stringify(makeValidationData()));`で投入する。投入前の原文は端末内の別キーにも退避・照合される。投入後は通常保存が拒否されるため、**JavaScript全体をReloadしてから操作する**（Fast Refreshではない）。製品ビルドにはこの操作入口を設置しない。

| --- | --- |

### 失敗条件の作り方と実機確認の補足

`d.failNextWrites(1)`で次の保存1回（退避保存も含む）を失敗させる。0で解除。`d.holdNextWrite()`で次の保存を保留し、`d.releaseWrite()`で解除する。`await d.readRaw()`で保存原文、`await d.readBackups()`で退避キーと原文を確認できる。予期しないAppState変更が先に保存を消費した場合は、対象操作の直前に失敗を指定し直す。

- M04〜M07/M09/M15: 10秒計測→背景/ロック/画面外に20秒→復帰し、同じセッションで不在時間を加算しないことを確認。黒画面のみなら継続、黒画面中のロックなら停止。停止直前または再開直前に保存失敗を指定し、通知・停止維持・再試行後の不加算を確認する。日記入力中も停止し、停止保存が失敗しても終了時刻を保持する。共通画面・日記・黒画面の再試行を確認。保存保留中に背景へ移動した場合も解除後に誤再開しないこと。
- M13/M14: 基準v7で終了→日記入力後に保存失敗を指定。失敗時はNT 180・完了1回・日記1件のまま。再試行/連打後は日記が1件だけ増え、NTは180+終了時点の実集中秒。第1話の追加分岐購入も失敗時180、成功時120、再操作で再課金なし。サイド購入は第2話の既読データをunlockedStoriesへ追加して投入し、挨拶を終えてから102の購入失敗/再試行を確認する。
- M16: 一度正常停止を保存し、再開後に強制終了。20秒後に起動して保存済み累積・履歴・NT・購入を照合。不明時間は加算せず、未保存区間の損失は許容する。過去のrunningSinceを持つデータでも同様に確認する。
- M17: 各不正データを投入・Reloadし、再読込や初期化確認のキャンセルで原文が変わらないことを確認。初期化実行直前に保存失敗を指定しても原文を保持し、明示的な再試行成功時だけ退避して初期化する。復旧確認は保全したコピーを修復するか正常データへ戻し、Reloadする。
- M18: 各旧形式を投入・Reloadし、上表の保持値、主キーのschemaVersion 7、再起動後の一致を確認。v5の欠落日付以外の既存日付を動かさない。

### 実装範囲と保存形式

- 新規開始ボタンの呼出時に、キューの待機前に`startInfo={startedAt, startedDate, startedTime}`を取得。停止・再開・再起動の停止正規化では変更しない。計測区間のルールは従来のまま。
- 正常完了ログへ開始情報と`logDate`を保存。カレンダーの印・一覧・合計は開始日のlogDate、今日の完了・日次解放は終了時刻のcompletedDateを使う。日跨ぎも分割しない。キャンセルは記録なし。
- ログに選択日の時分秒合計、開始時刻・集中時間・日記を追加。開始日は各記録の項目にしない。既存モーダルに日記編集・保存・キャンセル・文字数表示を追加。1000文字/空可。保存失敗は原日記と下書きを保持して再試行できる。
- ホームはローカル0時・active復帰・30秒ごとの時計再確認で当日を更新。解放案内は当日初回前・当日解放済み・全話解放済みを区別。カタログは3話のまま。14話化はA06の別作業。
- 保存キーは`@my-june/app-state-v1`のまま、schemaVersionは7→8。番号なし/v0〜v7は既存の互換補完後にv8へ移行保存する。旧ログは`logDate=元のcompletedDate`、開始情報はnull。旧v5で日付が元々欠落したものだけ従来の補完を継続。旧タイマーも開始情報nullで、完了時は従来どおり終了日に所属し開始時刻「記録なし」。v1以前の旧startedAtを新しい開始情報へ転用しない。
- 履歴・残高・購入・告知・解放・分岐・既読・累積を保持する。破損保全・保存成功前の業務状態不確定・同期停止・保存中の停止維持を変更しない。v7の必須配列欠落を空配列へ変換しない。旧日記が1000文字を超えていても移行時に切り捨てず、編集保存時に上限を適用する。
