## 共通背景の反映（2026-10-20）

対象: A07・M28。背景画像は各画面で指定し、重複する画像の描画処理だけを`src/components/common/ScreenBackground.tsx`へまとめた。`AppFrame`内の背景用state・描画分岐・画像一覧と、背景登録用Context・`useAppFrameBackground.ts`は削除した。`app/_layout.tsx`のStack共通画面レイアウト（`screenLayout`）は、ヘッダー・フッター・エラー表示を持つ`AppFrame`を配置する。画像やキャラクターの表示は扱わない。

画像を差し替える場合は、その画面の`ScreenBackground`の`source`を変更する。新しい画像も静的な`require`で指定する。

```tsx

```

`ScreenBackground`は`useWindowDimensions()`で画面高を取得して通常の`Image`を絶対配置するだけの部品とし、状態・Context・登録処理を持たない。各画面のルートから呼び出し、ヘッダーは透明のまま上端に重ねる。本文に上端Safe Area＋ヘッダー高（76）の余白を確保して、従来の本文開始位置を維持する。タブバーはフッターの直上に重ね、4タブの本文下側にタブバー高（70）の余白を設ける。高さは各使用箇所に直接記載し、`theme.ts`の`Layout`追加は取り消した。タイマーのデータなし・不正な会話パラメーターの案内にも背景を表示する。保存／BGMのエラーと再試行はフッター直上に配置する。以下の同日の記録にある共通フレームでの画像描画・画像一覧・登録フック・ルート別判定は変更前の構成であり、現在は本節を優先する。

各画面の画像を中央配置し、縦横比を保って画面全体を埋める（cover）。余る部分は切り抜く。ヘッダー背後からコンテンツまで連続させ、Tabsの場面は透明にする。背景はスクロールと独立し、タップ・読み上げの対象にしない。フッター、カード・会話枠・Modalの配色、タイマーの黒画面は既存設定を維持する。

### 失敗条件の作り方と実機確認の補足

- 新規開始ボタンの呼出時に、キューの待機前に`startInfo={startedAt, startedDate, startedTime}`を取得。停止・再開・再起動の停止正規化では変更しない。計測区間のルールは従来のまま。

- 履歴・残高・購入・告知・解放・分岐・既読・累積を保持する。破損保全・保存成功前の業務状態不確定・同期停止・保存中の停止維持を変更しない。v7の必須配列欠落を空配列へ変換しない。旧日記が1000文字を超えていても移行時に切り捨てず、編集保存時に上限を適用する。
