# TOVAL

**タスクを完了すると、1日1話ストーリーが進む習慣化アプリ。**

TOVALは、勉強などのタスクに取り組んだ直後に、ストーリーを報酬として受け取れるアプリです。「続きが読みたい」という気持ちを、翌日も取り組むきっかけにつなげることを目指しています。

ストーリーは全60話を予定しています。約2か月間、1つのタスクの継続を後押しすることで、習慣化の基盤を作ることを目標としています。

> 現在開発中です。UIデザイン・画像素材・ストーリー本文には仮のものが含まれます。現在のメインストーリーは3話で、全60話は正式版に向けた計画です。  
> 本READMEは、2026年10月24日の企業レビュー会に向けて、2026年10月18日に確認したmainブランチのコードと開発計画をもとに作成しています。

## 使い方

1. 習慣にしたいタスクを1つ登録し、目標時間を設定します。
2. タイマーを起動し、タスクに取り組みます。
3. 目標時間に達したら「終了して記録」を押し、必要に応じてふりかえりメモを残します。
4. その日初めてのタスク完了で、次のストーリーが1話解放されます。
5. 解放されたストーリーを読み、翌日もタスクに取り組みます。

メインストーリーの解放は1日1話までですが、タイマーは1日に何回でも利用できます。

## 主な機能

| 機能       | 内容                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| タイマー   | 目標時間をカウントダウンします。目標時間を過ぎると超過時間のカウントアップに切り替わり、終了時に計測時間1秒につき1NTを獲得できます。 |
| ストーリー | その日初めてタスクを完了すると、次の1話が解放されます。会話の文字送りや選択肢による分岐を実装しています。                            |
| メモリー   | 解放済みのメインストーリーを読み返せます。                                                                                           |
| ログ       | 記録のある日をカレンダーに表示します。日付を選ぶと、各回の取り組み時間とふりかえりメモを確認できます。                               |
| ショップ   | 貯めたNTを消費して追加の会話を解放できます。継続に加えて、取り組む時間を増やす動機につなげることを目指しています。                   |
| BGM音量    | メニューの標準スライダーで0〜100%に調整します。初期30%、0%で無音となり、指を離すと保存して再起動後も保持します。                       |
| タブ効果音 | 4つのタブを押すと効果音が鳴ります。メニューでBGMと独立して0〜100%に調整でき、初期100%、0%で効果音だけが無音になります。                  |

BGM音量とタブ効果音の記述は2026年10月24日の追加実装を反映しています。両音量は操作中にその場で変わり、保存に失敗した場合は保存済みの音量へ戻して再試行できます。選択中のタブを再び押しても効果音が鳴り、アプリ内の自動遷移では鳴りません。これらの変更のiPhone実機確認は未実施です。その他のレビュー用本文は、冒頭に記載した確認時点の内容です。

### 現在のタイマーの動作

- 目標時間に達しても自動では終了せず、終了操作まで超過時間を計測します。
- 目標時間前にキャンセルした場合、その回の時間・NT・完了記録・ストーリー解放は反映されません。
- アプリが非アクティブになるか、タイマー画面を離れると計測を一時停止し、アクティブなタイマー画面へ戻ると再開します。
- アプリ内の「省電力モード」では画面を黒くし、計測を継続します。

## 特にレビューしていただきたい点

### 1. ログ画面の情報量と表示方法

現在は、タスクの完了記録がある日をカレンダーで確認でき、日付を選ぶと取り組み時間やふりかえりメモを表示する構成です。継続の実感やモチベーションにつなげたい一方で、情報量が少なすぎるのではないかと懸念しています。

以下の点について、ご意見をいただきたいです。

- 現在の情報だけで、取り組みをふりかえり、継続を実感できるか。
- 取り組み時間の合計や、1週間の取り組み時間の棒グラフなどを追加する必要があるか。
- その日の合計取り組み時間をカレンダー上に表示する場合、どのような見せ方が分かりやすいか。

チーム内でもカレンダー上に時間を表示する案が出ましたが、見やすい表示方法を決められず、現時点では採用していません。

### 2. ユーザーデータ・ストーリーデータの管理

現在、ユーザーデータはAsyncStorageを利用して端末内に保存しています。ログイン認証を実装し、Supabaseなどで管理する方法へ移行するべきか迷っています。

また、ストーリー本文はTypeScriptの静的データとしてリポジトリ内に保存しています。今後メインストーリーを60話まで増やし、頻繁に編集することを考えると、管理方法を見直す必要があるのではないかと考えています。

以下の点について、ご意見をいただきたいです。

- 現在の規模や体験版の段階では、端末内保存を継続する判断は妥当か。
- 機種変更時の引き継ぎやデータ保護を考えた場合、ログイン認証・クラウド同期をどの段階で導入するべきか。
- ストーリーの話数や更新頻度を踏まえて、リポジトリ内の静的データと外部での管理をどう判断するべきか。
- データの種類、セキュリティ、開発・運用の負担を考えたとき、現段階では何を優先するべきか。

## 起動方法

Node.jsとnpm、および利用するExpo SDKに対応した実行環境を用意してください。

```bash
git clone https://github.com/samezima10101/TOVAL.git
cd TOVAL
npm install
npm run start
```

Expoの開発サーバー起動後、対応するExpo Goまたは開発ビルドからアプリを開いてください。Expo Goを利用する場合は、プロジェクトのSDKへの対応を確認してください。

`package.json`には、プラットフォーム別の起動コマンドも用意しています。

| コマンド          | 用途                          |
| ----------------- | ----------------------------- |
| `npm run ios`     | iOS向けの開発サーバー起動     |
| `npm run android` | Android向けの開発サーバー起動 |
| `npm run web`     | Web向けの開発サーバー起動     |

iOSシミュレーターの利用にはmacOSとXcode、Androidエミュレーターの利用にはAndroidの開発環境が必要です。Webでの起動コマンドはありますが、レビュー時はモバイル環境を中心にご確認ください。

設定ファイルやパッケージ名などには、旧名称の「MyJune」「myjune」が残っています。

### レビュー時に試していただきたい操作

1. タスクを登録し、短い目標時間でタイマーを開始する。
2. 目標時間に達した後、「終了して記録」から任意のメモを残し、ストーリーを読む。
3. メモリーで解放済みのストーリーを読み返す。
4. ログで当日の取り組み時間とメモを確認する。
5. ショップで、条件を満たした追加会話をNTで解放する。
6. 同じ日にもう一度タスクを完了し、NT・ログが追加され、メインストーリーは追加解放されないことを確認する。

## 開発体制と苦労したこと

企画・開発進行を担当する発案者が、バックエンド担当・デザイン担当と役割を分担して開発しています。

### イメージの共有とタスク分担

自分のイメージを言語化し、実装やデザインに必要な作業へ落とし込み、計画を立てて担当者に振り分けることに苦労しました。

### AIを用いた開発での要件整理

要件定義をもとにAIへ機能実装を依頼しましたが、要件の詰めが甘く、意図しない仕様や過剰な実装・テストが生まれました。

その結果、一通りの機能を作り終えた後に、仕様やワークフローを洗い出し、不要な部分を削る作業が必要になりました。AIに任せる前に、必要な動作と実装範囲を具体的に整理する難しさを実感しました。
