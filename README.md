# TOVAL

**タスクを完了すると、1日1話ストーリーが進む習慣化アプリ。**

TOVALは、勉強などのタスクに取り組んだ直後に、ストーリーを報酬として受け取れるアプリです。「続きが読みたい」という気持ちを、翌日も取り組むきっかけにつなげることを目指しています。

ストーリーは全60話を予定しています。約2か月間、1つのタスクの継続を後押しすることで、習慣化の基盤を作ることを目標としています。

> 現在開発中です。メインストーリー14話・各2分岐とサイド会話3件を実装しています。第1話の原稿とキャラクターの表情素材を反映していますが、仮本文・仮デザインも残っており、正式素材・Figmaデザインの全面反映は未完了です。全60話は正式版に向けた計画です。
>
> 本READMEは2026年10月24日時点の実装と開発計画を反映しています。今回の完成判定対象はiPhoneです。iPhoneでの回帰検証とTestFlight配布は未完了で、実装済みの機能も受け入れ合格とは区別しています。

## 使い方

1. 習慣にしたいタスクを1つ登録し、目標時間を設定します。
2. タイマーを起動し、タスクに取り組みます。
3. 目標時間に達したら「終了して記録」を押し、必要に応じてふりかえりメモを残します。
4. その日初めてのタスク完了で、次のストーリーが1話解放されます。
5. 解放されたストーリーを読み、翌日もタスクに取り組みます。

メインストーリーの解放は1日1話までですが、タイマーは1日に何回でも利用できます。

## 主な機能

| 機能       | 内容                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| タイマー   | 目標時間をカウントダウンします。目標時間を過ぎると超過時間のカウントアップに切り替わり、終了時に計測時間1秒につき1NTを獲得できます。 |
| ストーリー | その日初めてタスクを完了すると、次の1話が解放されます。会話の文字送りや選択肢による分岐を実装しています。                            |
| メモリー   | 解放済みのメインストーリーを読み返せます。                                                                                           |
| ログ       | 記録のある日をカレンダーに表示します。日付を選ぶと、その日の合計集中時間、各回の開始時刻・集中時間・日記を確認し、日記を編集できます。 |
| ショップ   | 貯めたNTを消費して追加の会話を解放できます。継続に加えて、取り組む時間を増やす動機につなげることを目指しています。                   |
| BGM音量    | メニューの標準スライダーで0〜100%に調整します。初期30%、0%で無音となり、指を離すと保存して再起動後も保持します。                       |
| タブ効果音 | 4つのタブを押すと効果音が鳴ります。メニューでBGMと独立して0〜100%に調整でき、初期100%、0%で効果音だけが無音になります。                  |
| メニュー設定 | タスク名・ユーザー名、通知時刻、タイマーのデフォルト時間を変更し、端末内に保存できます。デフォルト時間の初期値は25分です。 |
| ローカル通知 | 設定した時刻に毎日通知する処理を実装しています。初期時刻は21:30で、端末の通知許可が必要です。 |

両音量は操作中にその場で変わり、保存に失敗した場合は保存済みの音量へ戻して再試行できます。選択中のタブを再び押しても効果音が鳴り、アプリ内の自動遷移では鳴りません。音量調整と通知のiPhone実機確認は未実施です。通知本文は完成基準との相違が残っており、受け入れ前に調整が必要です。

メインストーリーは各話に2つの分岐があり、最初の選択は無料です。もう一方はNTで一度購入すると繰り返し再生できます。ショップではサイド会話3件を扱い、追加分岐・サイド会話の現在の価格は各60NTです。

### 現在のタイマーの動作

- 目標時間に達しても自動では終了せず、終了操作まで超過時間を計測します。
- 目標時間前にキャンセルした場合、その回の時間・NT・完了記録・ストーリー解放は反映されません。
- アプリが非アクティブになるか、タイマー画面を離れると計測を一時停止し、アクティブなタイマー画面へ戻ると再開します。
- アプリ内の「省電力モード」では画面を黒くし、計測を継続します。
- 目標時間は0分〜23時間55分で設定でき、0分でも利用できます。全14話を解放した後も、タイマー・NT獲得・記録を利用できます。

## 起動方法

Node.js **22.15.0**、npm **10.9.2**と、Expo SDK 58に対応したExpo Goまたは開発ビルドを用意してください。

```bash
git clone https://github.com/samezima10101/TOVAL.git
cd TOVAL
npm ci
npm run start
```

Expoの開発サーバー起動後、同じネットワークのiPhoneからアプリを開いてください。Windowsで追加引数を渡す場合は`npm.cmd`を使います。環境の再現やネイティブビルドの注意点は[開発運用手順](docs/development-operations.md)を参照してください。

`package.json`には、プラットフォーム別の起動コマンドも用意しています。

| コマンド          | 用途                          |
| ----------------- | ----------------------------- |
| `npm run ios`     | iOS向けの開発サーバー起動     |
| `npm run android` | Android向けの開発サーバー起動 |
| `npm run web`     | Web向けの開発サーバー起動     |

iOSシミュレーターの利用にはmacOSとXcode、Androidエミュレーターの利用にはAndroidの開発環境が必要です。Android・Web・iPadは今回の完成判定に含めず、iPhoneで確認します。

設定ファイルやパッケージ名などには、旧名称の「MyJune」「myjune」が残っています。

## 開発体制と苦労したこと

企画・開発進行を担当する発案者が、バックエンド担当・デザイン担当と役割を分担して開発しています。

### イメージの共有とタスク分担

自分のイメージを言語化し、実装やデザインに必要な作業へ落とし込み、計画を立てて担当者に振り分けることに苦労しました。

### AIを用いた開発での要件整理

要件定義をもとにAIへ機能実装を依頼しましたが、要件の詰めが甘く、意図しない仕様や過剰な実装・テストが生まれました。

その結果、一通りの機能を作り終えた後に、仕様やワークフローを洗い出し、不要な部分を削る作業が必要になりました。AIに任せる前に、必要な動作と実装範囲を具体的に整理する難しさを実感しました。
